# 问卷设计

> 问卷站（`apps/data`，与检测站分开部署）0.4.0 的问卷结构，2026-10-01 定稿。字段 schema 以 `packages/shared/src/survey.ts`（问卷）与 `snapshot.ts`（检测快照）为准，本文写题目文案、显示条件与取舍理由。

## 原则

- **一份问卷 = 一个 Claude 账号**。多账号分别填，同环境账号数单独问（C8）。
- **先问状态再分支**：状态决定是否出现封禁详情。
- **全部封闭式选项 + 「不清楚」**：方便统计，不逼人乱选。自由文本只有三处（邮箱后缀、Google Play 其他付款方式、补充说明）。
- **时间到月**；封禁日期可选精确到日，用于识别封号潮。
- **纵向更新**：提交后给匿名管理链接，正常账号被封后回来改状态。每次状态变化记一条事件（旧状态 → 新状态 + 日期），看板据此按「账号·月」算风险。
- **样本天然偏向被封者**：看板不报绝对封禁率，只做组间对比并附置信区间。

## 流程

5 步向导，每步一类问题，顶部显示进度；每步点「下一步」时只校验本步，提交时再整体校验一遍。

| 步骤 | 内容 |
|---|---|
| 01 账号状态 | A1–A2；被封的账号在本步接着答 B1–B4（总步数始终是 5） |
| 02 账号来历 | C1–C9 |
| 03 网络环境 | D1 一致 → D2 检测站带入（粘贴结果码）或手动；不一致 → 手动填写 M1–M5 |
| 04 使用习惯 | E1–E7 |
| 05 确认提交 | 按步汇总全部答案（可点回某步修改）+ F1 补充说明 + 提交 → 管理链接 |

浏览器后退键回到上一步；有答案未提交时关闭页面会提示。

## 题目

### A 账号状态（必答）

| # | 字段 | 题 | 选项 |
|---|---|---|---|
| A1 | `status` | 账号当前状态 | 正常使用 / 已被封禁 / 被封后申诉恢复 |
| A2 | `registeredAt` | 注册时间 | 年-月 / 不清楚（买来或共享的账号） |

### B 封禁详情（A1 ≠ 正常使用）

| # | 字段 | 题 | 选项 |
|---|---|---|---|
| B1 | `bannedAt` | 封禁日期 | 年-月，日选填 |
| B2 | `banAfter` | 注册后多久被封 | 注册当场 / 24 小时内 / 1–7 天 / 1–4 周 / 1–3 月 / 3 月以上 / 不清楚 |
| B3 | `banTriggers` | 被封前后发生了什么（多选） | 刚注册 / 刚付款订阅 / 刚通过 KYC 身份验证 / 刚换节点或地区 / 新设备登录 / 高强度用 Claude Code / 没有明显事件 / 不清楚 |
| B4 | `appeal` | 申诉（仅「已被封禁」） | 没申诉 / 申诉中 / 被拒 / 无法申诉 |

「被封后申诉恢复」即申诉成功，所以 B4 不问、也没有「成功」选项。

### C 账号来历

| # | 字段 | 题 | 选项 |
|---|---|---|---|
| C1 | `source` | 账号来源 | 自己注册 / 买的成品号 / 别人共享（拼车）/ 公司分配 |
| C2 | `login` | 登录方式 | Google / 邮箱 / Apple |
| C3 | `emailType` | 邮箱类型（C2 = 邮箱） | Gmail / Outlook / iCloud / 其他（可填后缀 `emailDomain`） |
| C4 | `phone` | 手机号验证 | 海外实体卡 / 海外虚拟号（Google Voice 等）/ 接码平台 / 没被要求验证 / 不清楚 |
| C5 | `plan` | 订阅 | Free / Pro / Max 5x / Max 20x / Team 或 Enterprise / 只用 API |
| C6 | `payment` | 付款方式（C5 ≠ Free） | 银行卡直接支付 / App Store 订阅 / Google Play 订阅 / 代充 |
| C7 | `refund` | 退款（C5 ≠ Free 且被封过） | 全额 / 部分 / 没退 |
| C8 | `accountsInEnv` | 同一网络或设备下有几个 Claude 账号 | 1 个 / 2–3 个 / 4 个以上 |
| C9 | `envBanHistory` | 同一设备或网络下有没有别的账号被封过 | 有 / 没有 / 不清楚 |

C6 追问：

- **银行卡直接支付**：卡类型 实体卡 / 虚拟卡（必答）；卡号前 6 位（选填）；发卡地区（选填，在意隐私可以只填这个）
- **App Store 订阅**：Apple ID 所在区（必答，下拉选国家或地区）
- **Google Play 订阅**：实际付款方式 实体卡 / 虚拟卡 / 其他。选卡时，卡号前 6 位和发卡地区都是选填；选「其他」时可以填一句具体方式（如 PayPal、礼品卡）
- **代充**：不追问

退款放在付款方式后面，因为要先知道是否付费。

### D 网络环境

| # | 字段 | 题 | 选项 |
|---|---|---|---|
| D1 | `env.same` | 你现在的设备和网络，和这个账号平时用的（被封的账号：被封时用的）一致吗 | 一致 / 不一致 |
| D2 | `env.source` | 网络环境怎么填（D1 = 一致） | 用检测站自动获取 / 手动填写 |

D1 放在网络环境最前面：被封的人往往事后才来检测，环境可能已经换了，这种检测数据和封号对不上，所以不一致时只能手动填写。

**检测站路径**：问卷站与检测站是两个独立网站。问卷在新标签页打开检测站，检测完点「复制结果码」，回到问卷粘贴；问卷解析后逐项列出带入了什么（见下文「检测快照」）。问卷页一直开着，已填的答案不会丢。

**手动路径**（问的都是这个账号平时的环境，不是现在的环境）：

| # | 字段 | 题 | 选项 |
|---|---|---|---|
| M1 | `exitRegion` | 访问 Claude 时出口在哪个国家或地区 | 下拉 / 不清楚 |
| M2 | `exitType` | 出口类型 | 机场（共享节点）/ 自建 VPS / 静态住宅 IP / 商业 VPN / 境外手机卡流量 / 人在海外直接连 / 不清楚 |
| M3 | `proxyMode` | 代理模式（M2 ≠ 人在海外直接连） | 规则分流 / 全局 / TUN 虚拟网卡 / 软路由 / 不清楚 |
| M4 | `timezone` | 系统时区 | 中国时区 / 和出口地区一致 / 其他 / 不清楚 |
| M5 | `language` | 系统和浏览器语言 | 中文 / 英文 / 其他 |

M1–M5 对应检测快照里最主要的几项（出口地区、IP 类型、是否走代理、时区与语言）。WebRTC、DNS 泄露用户自己判断不了，不问。手动样本单独标记，统计时与检测样本分开。

### E 使用习惯

| # | 字段 | 题 | 选项 |
|---|---|---|---|
| E1 | `clients` | 用哪些客户端（多选） | 网页 / 桌面 App / iOS App / 安卓 App / Claude Code / API |
| E2 | `os` | 设备系统（多选） | Windows / macOS / Linux / iOS / 安卓 |
| E3 | `usageCap` | 用量上限 | 经常用满 / 偶尔用满 / 从没用满 |
| E4 | `chatLanguage` | 对话主要用什么语言 | 中文 / 英文 / 混合 |
| E5 | `sharing` | 谁在用这个账号 | 本人一台设备 / 本人多台设备 / 多人共用 |
| E6 | `reverseProxy` | 有没有用 CPA 或其他软件做逆向或反代（多选） | 没有 / CPA / 其他逆向或反代软件 |
| E7 | `jailbreak` | 有没有破限或 NSFW 使用 | 从不 / 偶尔 / 经常 / 不便回答 |

### F 补充（选填）

| # | 字段 | 题 |
|---|---|---|
| F1 | `note` | 还有什么想补充的（≤ 500 字，不要写邮箱、账号等能认出你的信息） |

## 检测快照

检测站生成、签名后，由用户以结果码复制到问卷。只放判定用的事实，并附检测站版本号与 commit（判定规则会变，留着可以回算）。

| 类别 | 带入 | 不带入 |
|---|---|---|
| 判定结果 | 每个检测项的「正常 / 注意 / 异常 / 未知」 | — |
| 出口 | claude.ai 出口国家 | 任何 IP |
| IP 属性 | ASN、运营商、两家数据源的网络类型、VPN / 代理 / Tor / 滥用 / 机房各由哪家标记、风险分、IP 段登记国家 | 城市 |
| 环境指纹 | 时区、浏览器语言（前 3 个）、区域格式、有没有非系统自带的中文字体、国产浏览器 / 设备名、系统与浏览器家族 | 字体清单、UA 原文 |
| 泄露 | WebRTC 结论（禁用 / 无泄露 / 泄露大陆 IP / 其他出口）、DNS 解析器所在国家 | 国内出口 IP 与国内运营商（隐私红线） |

token 机制（实现时可调整）：

- 检测站 Worker 签发。IP 属性由 Worker 按 IP hash 从自己的缓存回填，浏览器改不了；指纹与泄露由浏览器上报，可信度与问卷自报相同
- Ed25519 签名：检测站持私钥，数据站只持公钥
- 以「结果码」的形式由用户复制、粘贴到问卷，两站之间不直接传数据
- 有效期短（暂定 1 小时），一个 token 只能提交一次

## 隐私与公开数据

- 不收集：邮箱地址、账号 ID、任何 IP、国内网络信息
- 自由文本（`emailDomain`、Google Play 其他付款方式、`note`）不进公开数据集，只做人工归纳
- 邮箱后缀、卡号前 6 位属于低频值，看板和公开数据里只展示样本数 ≥ 5 的取值，其余合并为「其他」
- 管理链接是随机密钥，服务器只存它的 hash；凭链接可以修改或删除，删除即物理删除

## 校验

- 条件必填按上文各题的显示条件；不显示的题不得出现在提交内容里
- 日期：`registeredAt` ≤ `bannedAt` ≤ 提交当天
- 多选互斥：`banTriggers` 的「没有明显事件 / 不清楚」、`reverseProxy` 的「没有」与其他选项互斥
- 卡号前 6 位：`/^\d{6}$/`；地区：ISO 3166-1 alpha-2 大写
- `emailDomain`：转小写、合法域名格式；自由文本长度见 `TEXT_LIMITS`
- `env.same = false` 时只接受手动填写（类型上已约束）

## 留到数据站设计时定

- 存储结构、状态变更事件表、管理链接的具体交互
- 公开数据集的导出格式与频率
