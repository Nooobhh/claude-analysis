# 看板设计（草稿）

> 问卷站看板 `/board`（页面标题「问卷数据汇总」）的统计口径、分组规则与页面结构。2026-10-03 起草，**未定稿**。问卷字段见 `survey.md`，数据清洗规则见 `survey.md`「数据清洗」。

## 目标

账号被封大致有两类原因：

1. **地区不支持**：Anthropic 判定账号在不支持的地区使用。主要和**使用环境**（网络出口、设备指纹、身份地区信号）有关
2. **违反策略**：违反使用政策或服务条款。主要和**用户行为**有关

看板的主线是把两类分开看：

- 在**环境干净**的账号里，比较不同行为的被封占比：看行为造成的封禁
- 在**行为干净**的账号里，比较不同环境的被封占比：看环境造成的封禁

必须分层看：环境差的人往往行为也更冒险（买号、拼车、走机场），两样混在一起比较，会把一方的影响算到另一方头上。

## 原则

- 只展示汇总，不展示单份问卷。所有统计在问卷站 Worker 里算好再下发，浏览器拿不到逐份数据
- 样本偏向被封者：不报封号率，只做组与组之间的比较，并附 95% 区间
- 「干净」按公开规则分组：网络环境、设备指纹用加权扣分判定，只显示「通过 / 不通过」和扣分明细，不显示分数
- 分组规则只写在本文，改规则先改本文；判定以入库时的检测结果为准，检测站规则大改时再决定是否回算

## 统计口径

| 项 | 口径 |
|---|---|
| 被封 | A1 = 已被封禁，或被封后申诉恢复（即被封过） |
| 被封占比 | 被封份数 / 该组份数 |
| 区间 | Wilson 95% 区间（小样本比正态近似可靠） |
| 低样本 | 组内 < 30 份仍显示占比与区间，占比后标「低样本」 |
| 比较基准 | 当前样本范围的整体占比，写在每部分的说明里。例：在「环境干净」范围内比较行为时，基准 = 环境干净组整体的被封占比 |
| 多选题 | 每个选项单独算，分母 = 答了这题的份数 |
| 没问到 | 因显示条件没出现这题，或问卷版本里还没有这题：不进该维度的分母 |

## 环境判定

环境判定只看**网络环境**、**设备指纹**两类；账号、支付相关的题（C 组）只在「账号情况」里展示，不进判定。

每份问卷的网络环境、设备指纹各得出 **通过 / 不通过 / 无法判定**。**环境干净 = 两类都通过**；任一类不通过即「环境有问题」；否则任一类无法判定即「无法判定」。

规则在 shared `scoring.ts`，检测站结论卡与看板共用同一份：一个人在检测站看到「网络环境通过」，他的问卷在看板上也按同样规则分组。分数只用于判定，两站都只显示「通过 / 不通过」和扣分明细，不显示分数。权重是初始值，等 B5「封禁通知里写的原因」攒到足够样本再校准，改权重先改本节。

### 检测站样本

两类各从 100 分起扣，**扣到 60 分以下不通过**：

- **网络环境**：任何一项「异常」直接不通过（未走代理、出口不在支持地区、多个出口、IP 漂移、WebRTC 泄露大陆 IP、国内 DNS 解析器、两家都标记 VPN / 代理 / Tor / 滥用、高风险分）；「注意」按下表扣分
- **设备指纹**：这类检测项最多判到「注意」，全部按下表扣分

| 网络环境的「注意」 | 扣分 | 设备指纹的「注意」 | 扣分 |
|---|---|---|---|
| `ip.vpn` VPN 只有一家标记 | 15 | `fp.timezone` 中国或港澳时区 | 40 |
| `ip.proxy` 代理只有一家标记 | 15 | `fp.browser` 国产浏览器 | 30 |
| `ip.tor` Tor 只有一家标记 | 15 | `fp.device` 国产设备 | 20 |
| `leak.webrtc` WebRTC 出口与 Claude 不同 | 15 | `cross.timezone` 时区与 IP 不一致 | 20 |
| `leak.dns` 有港澳 DNS 解析器 | 15 | `fp.language` 浏览器语言含简体中文 | 10 |
| `ip.type` 机房 IP 或数据源分歧 | 10 | `cross.language` 语言与 IP 地区矛盾 | 10 |
| `ip.native` 广播 IP | 10 | `fp.locale` 简体中文区域格式 | 5 |
| `ip.abuser` 只有一家有滥用记录 | 10 | `fp.fonts` 中文环境字体 | 5 |
| `ip.score` 中风险分 | 10 | | |
| `exit.consistency` 部分域名请求失败 | 5 | | |

例：机场用户（机房 IP + 一家标记 VPN）网络 75 分，通过；中文系统和字体、时区跟着出口改了，设备指纹 70 分，通过；仍是中国时区（时区本身 + 与 IP 不一致）40 分，不通过。

- 不参与：`exit.claude` `exit.api`（能否访问）、`exit.domestic` `ip.asn` `ip.org` `ip.location`（纯信息）、`avail.*`（Claude 服务状态，与用户环境无关）
- 「未知」的项（检测失败）跳过、不扣分；一类里全是「未知」记为无法判定
- 命中数据清洗规则「检测设备不是使用设备」时，设备指纹记为无法判定，网络环境照常判定

### 手动填写样本

手动样本测不到 IP 风险标记和泄露，按自报的几项折算，同样 60 分以下不通过：

| 类 | 题 | 规则 |
|---|---|---|
| 网络环境 | M1 出口地区 | 不支持地区直接不通过；不清楚记为无法判定 |
| 网络环境 | M5 节点自动切换 | 会自动切换直接不通过（相当于 IP 漂移）；不清楚跳过 |
| 设备指纹 | M3 系统时区 | 中国时区扣 60（时区 40 + 与 IP 不一致 20）；其他扣 20；不清楚跳过 |
| 设备指纹 | M4 系统和浏览器语言 | 中文扣 20（语言、区域格式、字体三项合计） |
| 设备指纹 | M6 国产手机或浏览器 | 有扣 30；不清楚跳过 |

看板默认把两类样本合并。

## 行为判定

每份问卷得出 **行为 = 干净 / 有违规项 / 无法判定**，组合规则同上。「违规项」指按 Anthropic 的条款可能构成违规的做法，不是本站的评价。

| 题 | 干净 | 违规项 | 无法判定 |
|---|---|---|---|
| C1 账号来源 | 自己注册、公司分配 | 买的成品号、别人共享 | — |
| E5 谁在用 | 本人一台设备、本人多台设备 | 多人共用 | — |
| E6 逆向或反代 | 没有 | CPA、其他逆向或反代软件 | — |
| E7 破限或 NSFW | 从不 | 偶尔、经常 | 不便回答 |
| E8 蒸馏 | 没有 | 有 | 不便回答 |

第 1 版问卷没问 E8：没答的题跳过，不影响判定，按这份问卷问到的题判断。

同环境多账号（C8）、代充（C6）不算违规项，不影响判定，在「账号情况」里照常展示。其余 E 组的题（客户端、设备、用量、对话语言、高危用途等）只在「使用习惯」里比较，不进判定。

## 页面结构

整页围绕一张散点图展开，一个点 = 一份问卷，不用卡片；左侧有目录（窄屏在顶部）。样式见 DESIGN.md §3.2、§4.15–4.19。散点图下面按问卷分三块：账号情况（A+B+C）、网络环境（D）、使用习惯（E）。三块里每一项都写成具体的事实（如「时区与出口一致 / 不一致」），不用「通过 / 注意 / 异常」这类说法；通过与否只用于散点图分组。

| 顺序 | 部分 | 内容 |
|---|---|---|
| 1 | 标题 | 两类封号原因的说明；已收集份数、检测站带入份数、更新日期 |
| 2 | 散点图 | 横轴环境（干净 / 有问题）、纵轴行为（干净 / 有违规项），每份问卷一个点落进对应象限，颜色 = 状态。四角写各象限的被封过占比、区间、份数与各状态份数；无法判定的份数写在图下方 |
| 3 | 账号情况 | 全部样本，不切换范围，见下表 |
| 4 | 网络环境 | 默认取散点图下半边（行为干净），可切换到全部样本，见下表 |
| 5 | 使用习惯 | 默认取散点图左半边（环境干净），可切换到全部样本，见下表 |
| 6 | 判定说明 | 折叠：散点图的「环境干净」「行为干净」怎么判定 |

**账号情况**

| 组 | 项 | 展示 |
|---|---|---|
| 注册 | A2 注册时间（按年，不清楚单列） | 各组被封占比 |
| 封禁情况（只看被封过的账号） | B1 按月堆点的封禁时间线 | 每月被封的账号数 |
| | B2 使用多久后被封、B5 封禁通知里写的原因 | 按环境干净 / 有问题分两组的分布，验证「地区问题封得快」和通知原因是否与分组一致 |
| | B3 被封前后发生了什么、B4 申诉、C7 退款 | 分布（占被封账号的比例）；只有被封的账号答，算不了被封占比 |
| 账号来历 | C1 账号来源、C2 登录方式、C3 邮箱类型、C4 手机号验证、C5 订阅、C6 付款方式与卡类型 / 发卡地区 / Apple ID 所在区、C8 同环境账号数、C9 同环境别的号被封过 | 各组被封占比 |

**网络环境**

| 组 | 项 | 选项 | 来源 |
|---|---|---|---|
| 网络 | 出口 IP 一致（各域名同一个出口、不漂移） | 一致 / 不一致 | 检测站：多域名出口与 IP 漂移都正常为一致，任一项异常为不一致，其余不计入；手动：M5 固定 / 自动切换 |
| | 原生 IP | 原生 IP / 广播 IP | 检测站 |
| | 代理情况 | D2 各选项 | 两类样本 |
| | IP 风险标记 | 没有标记 / 有标记 | 检测站：VPN、代理、Tor、滥用四项有任何一家标记即「有」 |
| | 泄露 | 无泄露 / WebRTC 泄露 / DNS 泄露（多选，两种都有的两行都算） | 检测站：WebRTC、DNS 解析器的「注意」「异常」都算泄露 |
| 设备指纹 | 时区与出口 | 一致 / 不一致 | 检测站：时区与 IP 是否一致（检测设备不是使用设备的不计入）；手动：M3 和出口一致 / 中国时区或其他 |
| | 语言与格式与出口 | 一致 / 不一致（中文环境、出口不在中文地区） | 检测站：语言与 IP 地区矛盾，或区域格式是简体中文而出口不在中文地区，为不一致；手动：M4 中文且 M1 出口不在中文地区为不一致，出口不清楚不计入 |

中文地区 = 中国大陆、香港、澳门、台湾、新加坡、马来西亚（shared `ZH_SPEAKING`）。

**使用习惯**

| 项 | 选项 |
|---|---|
| 是否多客户端 | 单一客户端 / 多客户端（E1 选了 2 个以上） |
| 是否多设备 | 单一设备系统 / 多设备（E2 选了 2 种以上） |
| 用量上限 | E3 各选项 |
| 对话语言 | E4 各选项 |
| 谁在用这个账号 | E5 各选项 |
| 逆向或反代、破限或 NSFW、蒸馏、高危用途 | 各自分「有 / 没有 / 不便回答」比较被封占比：E6 选了 CPA 或其他为有；E7 偶尔、经常为有；E8 有；E9 选了网络安全、批量生成、自动化脚本任一为有 |

每项一个选项一行：选项名与份数、该组问卷画成一串点（按封禁、恢复、正常排）、被封占比与区间；分布类（只看被封账号）的右侧写占被封账号的比例。

散点图四个象限：

| | 环境干净（左） | 环境有问题（右） |
|---|---|---|
| **有违规项（上）** | 行为造成的封禁 | 两方面都有问题 |
| **行为干净（下）** | 基线：两方面都没问题仍被封的比例 | 环境造成的封禁 |

## 隐私

- `/api/board` 只返回汇总，不返回任何单份问卷的字段
- 散点图和点串里的点由前端按「每格各状态几份」生成，点在象限内的位置是随机铺的；不提供单个点的详情
- 低频取值合并：邮箱后缀、卡号前 6 位、发卡地区、Apple ID 区、ASN / 运营商，样本少于 5 份的取值合并为「其他」（在 `survey.md` 原有的邮箱后缀、卡号前 6 位之外，多加了后三项）
- 自由文本（`emailDomain` 原文、Google Play 其他付款方式、`note`）不进看板
- 以后做交叉筛选时，筛选结果少于 5 份的格子显示「< 5」

## 实现要点

- `GET /api/board`：Worker 读全表，按本文规则算好汇总，每个实例缓存 5 分钟（同 `/api/stats` 的做法）
- 判定规则写在问卷站 Worker 里，只在服务器上运行
- 支持地区列表在 `packages/shared/src/regions.ts`，检测站判定出口与看板判定手动填写的出口共用（两站互不导入对方代码）
