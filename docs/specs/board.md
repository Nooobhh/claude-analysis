# 看板设计（草稿）

> 问卷站看板 `/board` 的统计口径、分组规则与页面结构。2026-10-03 起草，**未定稿**。问卷字段见 `survey.md`，数据清洗规则见 `survey.md`「数据清洗」。

## 目标

账号被封大致有两类原因：

1. **地区不支持**：Anthropic 判定账号在不支持的地区使用。主要和**使用环境**（网络出口、设备指纹、身份地区信号）有关
2. **违反策略**：违反使用政策或服务条款。主要和**用户行为**有关

看板的主线是把两类分开看：

- 在**环境干净**的账号里，比较不同行为的被封占比：看行为造成的封禁
- 在**行为干净**的账号里，比较不同环境的被封占比：看环境造成的封禁

必须分层看：环境差的人往往行为也更冒险（买号、拼车、走机场），两样混在一起比较，会把一方的影响算到另一方头上。

## 原则

- 只展示汇总，不展示单份问卷。所有统计在问卷站 Worker 里算好再下发，浏览器拿不到逐份数据
- 样本偏向被封者：不报封号率，只做组与组之间的比较，并附 95% 区间
- 「干净」是按客观规则分组，不是评分：不加权、不出总分
- 分组规则只写在本文，改规则先改本文；判定以入库时的检测结果为准，检测站规则大改时再决定是否回算

## 统计口径

| 项 | 口径 |
|---|---|
| 被封 | A1 = 已被封禁，或被封后申诉恢复（即被封过） |
| 被封占比 | 被封份数 / 该组份数 |
| 区间 | Wilson 95% 区间（小样本比正态近似可靠） |
| 低样本 | 组内 < 30 份仍显示占比与区间，占比后标「低样本」 |
| 比较基准 | 当前样本范围的整体占比，写在每部分的说明里。例：在「环境干净」范围内比较行为时，基准 = 环境干净组整体的被封占比 |
| 多选题 | 每个选项单独算，分母 = 答了这题的份数 |
| 没问到 | 因显示条件没出现这题，或问卷版本里还没有这题：不进该维度的分母 |

## 环境判定

每份问卷得出 **环境 = 干净 / 有问题 / 无法判定**：任一项有问题就是「有问题」；否则任一项无法判定就是「无法判定」；全部满足才算「干净」。

### 检测站样本

检测快照里每个检测项的判定（正常 / 注意 / 异常 / 未知）分三类使用：

| 类 | 检测项 | 干净的要求 |
|---|---|---|
| 网络 | `exit.proxied` `exit.consistency` `exit.drift` `ip.region` `ip.native` `ip.type` `ip.vpn` `ip.proxy` `ip.tor` `ip.abuser` `ip.score` `leak.webrtc` `leak.dns` | 没有「异常」 |
| 设备指纹 | `fp.timezone` `fp.language` `fp.locale` `fp.fonts` `fp.browser` `fp.device` `cross.timezone` `cross.language` | 全部「正常」 |
| 不参与 | `exit.claude` `exit.api`（能否访问）、`exit.domestic` `ip.asn` `ip.org` `ip.location`（纯信息）、`avail.*`（Claude 服务状态，与用户环境无关） | — |

- 网络只要求「没有异常」：机房 IP、广播 IP、只有一家数据源标记、中风险分都是「注意」，用代理的人几乎都有，要求全部正常的话，干净组会接近空。这些「注意」项放进「使用环境」板块单独比较
- 设备指纹项最多只会判到「注意」，所以要求全部正常，否则等于没要求。这条可能偏严（简体中文系统语言很普遍）：先按它跑，看到分布再放宽
- 「未知」的项（检测失败）跳过，不影响判定
- 命中数据清洗规则「检测设备不是使用设备」时，设备指纹类记为无法判定，网络类照常使用

### 手动填写样本

| 题 | 干净 | 有问题 | 无法判定 |
|---|---|---|---|
| M1 出口地区 | 支持地区 | 中国大陆、港澳等不支持地区 | 不清楚 |
| M3 系统时区 | 和出口地区一致 | 中国时区、其他 | 不清楚 |
| M4 系统和浏览器语言 | 英文、其他 | 中文 | — |
| M5 节点自动切换 | 固定用一个 | 会自动切换 | 不清楚 |
| M6 国产手机或浏览器 | 没有 | 有 | 不清楚 |

手动样本测不到 IP 风险标记和泄露，「干净」只代表自报的几项正常。看板默认把两类样本合并，可以切换成「只看检测站样本」。

### 两类样本共用

| 题 | 满足 | 有问题 | 跳过 |
|---|---|---|---|
| C9 同一设备或网络下别的账号被封过 | 没有 | 有 | 不清楚 |

别的号被封过，说明这套环境可能已被关联标记，算环境问题。「不清楚」很常见，跳过、不影响判定，免得大批样本变成无法判定。

## 行为判定

每份问卷得出 **行为 = 干净 / 有违规项 / 无法判定**，组合规则同上。「违规项」指按 Anthropic 的条款可能构成违规的做法，不是本站的评价。

| 题 | 干净 | 违规项 | 无法判定 |
|---|---|---|---|
| C1 账号来源 | 自己注册、公司分配 | 买的成品号、别人共享 | — |
| E5 谁在用 | 本人一台设备、本人多台设备 | 多人共用 | — |
| E6 逆向或反代 | 没有 | CPA、其他逆向或反代软件 | — |
| E7 破限或 NSFW | 从不 | 偶尔、经常 | 不便回答 |

**异常行为**：另做标记，不算违规项，不影响上面的判定，在「用户行为」板块里单独成组比较。

| 题 | 标记为异常行为 |
|---|---|
| C8 同环境账号数 | 2–3 个、4 个以上 |
| C6 付款方式 | 代充 |

以下几项属于正常使用，不进判定，只在「用户行为」板块里比较：E1 客户端、E3 用量上限、C5 订阅档位。

## 页面结构

整页围绕一张散点图展开，一个点 = 一份问卷，不用卡片。样式见 DESIGN.md §3.2、§4.15–4.18。

| 顺序 | 部分 | 内容 |
|---|---|---|
| 1 | 标题 | 两类封号原因的说明；已收集份数、检测站带入份数、更新日期 |
| 2 | 散点图 | 横轴环境（干净 / 有问题）、纵轴行为（干净 / 有违规项），每份问卷一个点落进对应象限，颜色 = 状态。四角写各象限的被封过占比、区间、份数与各状态份数；无法判定的份数写在图下方 |
| 3 | 用户行为 | 取散点图左半边（环境干净），可切换到全部样本。维度：行为判定的 4 题、异常行为（C8、代充）、E1 / E3 / C5、B3 里的行为类事件（高强度用 Claude Code、进行过反代） |
| 4 | 使用环境 | 取散点图下半边（行为干净），可切换到全部样本。分四组：网络（D2 代理情况与网络类检测项、M1 / M5）、设备指纹（指纹类检测项、M3 / M4 / M6）、身份地区信号（C4 手机号、C6 卡类型 / 发卡地区 / Apple ID 区、C2 / C3 登录方式）、关联（C9 同环境别的号被封过、B3 里的换节点 / 新设备） |
| 5 | 封号时间 | B1 按月堆点的封禁时间线；B2「使用多久后被封」按环境干净 / 有问题分两组，验证「地区问题封得快、行为问题封得慢」 |
| 6 | 判定说明 | 折叠：「环境干净」「行为干净」与「异常行为」怎么判定 |

3、4 每个选项一行：选项名与份数、该组问卷画成一串点（按封禁、恢复、正常排）、被封占比与区间。

散点图四个象限：

| | 环境干净（左） | 环境有问题（右） |
|---|---|---|
| **有违规项（上）** | 行为造成的封禁 | 两方面都有问题 |
| **行为干净（下）** | 基线：两方面都没问题仍被封的比例 | 环境造成的封禁 |

## 隐私

- `/api/board` 只返回汇总，不返回任何单份问卷的字段
- 散点图和点串里的点由前端按「每格各状态几份」生成，点在象限内的位置是随机铺的；不提供单个点的详情
- 低频取值合并：邮箱后缀、卡号前 6 位、发卡地区、Apple ID 区、ASN / 运营商，样本少于 5 份的取值合并为「其他」（在 `survey.md` 原有的邮箱后缀、卡号前 6 位之外，多加了后三项）
- 自由文本（`emailDomain` 原文、Google Play 其他付款方式、`note`）不进看板
- 以后做交叉筛选时，筛选结果少于 5 份的格子显示「< 5」

## 实现要点

- `GET /api/board`：Worker 读全表，按本文规则算好汇总，每个实例缓存 5 分钟（同 `/api/stats` 的做法）
- 判定规则写在问卷站 Worker 里，只在服务器上运行
- 支持地区列表现在在检测站 `apps/detect/src/lib/regions.ts`，问卷站要用：挪到 `packages/shared`（两站互不导入对方代码）
